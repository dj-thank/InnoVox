# Macで使うInnoVox

更新: 2026-09-26。OSの機能、InnoVoxの実装、実機での確認を分けて記載します。
この文書を作成した作業環境はWindowsです。GitHubの`macos-26-arm64`環境では
Node.js 24.19.0で共通ランタイムのテストが成功しました。対象コミットと件数は[検証記録](../verification.md)
を参照してください。Macでのマイク・画面・権限操作はまだ実機確認していません。
CIのMac実行はネイティブ音声や画面取得、Intel Mac互換性の証明にはなりません。

## 今回の初版で使う経路

Macでも、Node.js 24とブラウザで共通のWeb画面とサーバーを実行する構成です。
クラウドのInnoVoxにブラウザで接続する場合、Macにサーバーを置く必要はありません。
ローカルのCodex/Claude Code履歴を読む場合は、そのMacでコレクターを動かします。

- **プロジェクトの前提・確認・回答の保存**: 共通のTypeScript/SQLite実装。
- **Codex/Claude Codeの会話ログ取り込み**: 選択したJSONLファイルの、対応する発言形式を取得。
  指定したログルートと作業ディレクトリの範囲内で、複数セッションの検出・初回取り込み・追記監視も可能です。
  隠れた推論、任意のツール入出力、アプリ内の全セッション取得は対象外です。
- **Astraによる先回りの確認**: プロジェクトごとに自動分析を有効化するか、明示的に分析を開始。
  APIキーと対象モデルへのアクセスが必要です。Windowsの開発環境では実APIの構造化応答を確認済みです。
- **GPT Live音声相談**: ブラウザのWebRTC接続を実装。HTTPSまたはlocalhostと
  マイク許可が必要です。Windowsでは別経路のWebSocket音声出力が成功しましたが、
  Macのブラウザ接続・マイク・人間による聴取は未確認です。
- **音声での回答確定**: Astraによる返答解釈・読み返し・明示的な音声確認の処理を
  実装し、合成のメディアイベントとHTTPで確認しています。実音声での正確さは未確認です。
- **返答の反映**: 回答を保存し、送信先を保持した状態でコピーできます。
  任意で起動するCodex App Server接続部は、指定セッションへの返送を実装しています。
  Windows上の隔離したCodex実行環境で保存まで確認済みですが、Mac実機と通常のDesktopへの接続は未確認です。
  Claudeへの返送は未実装です。コピー、API受理、ログへの保存、モデルによる利用を分けて表示します。
  起動方法と制約は[接続ガイド](../connectors.md)を参照してください。

## Macで追加できるネイティブ機能

以下はmacOSの提供する接続口を使った今後の実装候補です。
現行のWeb画面に権限を与えても、未実装機能が有効になるわけではありません。

### 画面・ウィンドウ・アプリ音声

ScreenCaptureKitは、選択した画面、アプリ、ウィンドウの映像・音声を取得するための
Appleの接続口です。システムの共有ピッカーを使い、対象を限定する方向にします。
静止画の差分を優先し、変更のない画像をAstraへ繰り返し送らない設計が必要です。
Appleの現在のサンプルはmacOS 15 / Xcode 16以降を条件にしています。
これはサンプルの条件であり、ScreenCaptureKit全体の初出バージョンを意味しません。
[Apple: ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit)
・[画面取得サンプル](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)

### 画面の文字とアプリ操作

Accessibility APIを使えば、対応するアプリのUI要素や公開されている文字を扱う
ネイティブ接続部を設計できます。ただし、アプリが公開しない要素・非表示の履歴・
認証が必要な情報まで読めるとは限りません。画面の文字とLLMへ実際に渡された
コンテキストも別です。自動入力には、対象アプリ・セッションの再確認と配送記録を伴わせます。
[Apple: アクセシビリティによるアクセス](https://support.apple.com/guide/mac-help/mh43185/mac)

### Appshotsとの関係

OpenAIのAppshotsは前面ウィンドウの画像と取得可能な文字を会話へ添付する機能です。
InnoVoxが使える汎用の常時監視APIとは確認できていません。InnoVoxのコレクター、
将来のネイティブ画面取得、Appshotsは別の能力として扱います。
[OpenAI: Appshots](https://learn.chatgpt.com/docs/appshots)

## 権限の設定

「システム設定 → プライバシーとセキュリティ」で、利用するアプリに必要な範囲だけ
許可します。表示名はmacOSの版・言語で変わることがあります。

1. **マイク**: ブラウザで音声相談を始めるときに許可します。OSのブラウザ権限に加え、
   Webサイト単位のマイク許可も確認します。入力装置の選択、ミュート、出力音量は別です。
   [Apple: マイク](https://support.apple.com/guide/mac-help/mchla1b1e1fe/mac)
2. **画面収録とシステムオーディオ録音**: 将来の画面・アプリ音声取得を使用するときだけ必要です。
   GPT Liveへ自分の声を送るだけなら、画面収録を有効にする必要はありません。
   [Apple: 画面と音声の収録](https://support.apple.com/guide/mac-help/mchld6aa7d23/mac)
3. **アクセシビリティ**: 将来のUI要素取得・操作に使うネイティブ接続部へ付与します。
   初版のログ読み取りやブラウザのマイク入力には要求しません。
4. **オートメーション**: 将来Apple Eventsで他アプリへ操作を依頼する実装を選んだ場合に、
   宛先アプリごとの許可が必要になります。アクセシビリティ許可と同一ではありません。
5. **ファイルとフォルダ**: ログが保護されたフォルダにある場合、そのファイルにアクセスする
   実行元の許可を確認します。Terminal/iTerm経由とパッケージアプリでは許可対象が異なります。
   フルディスクアクセスを初期必須条件にはしません。
   [Apple: ファイルアクセス](https://support.apple.com/guide/security/secddd1d86a6/web)
6. **入力監視**: 他アプリ使用中のキーボード等の監視用です。初版は使用しません。
   [Apple: 入力監視](https://support.apple.com/guide/mac-help/mchl4cedafb6/mac)

GPT Liveの音声経路はOpenAIへ接続します。Appleの音声認識を使う実装ではないため、
Apple音声認識の権限を代わりに有効にしても、マイクやGPT Liveの接続問題は解決しません。

OS権限は利用者が設定します。アプリが自分で包括的な許可を付与したり、TCCやSIPを
無効にしたりする方法は採用しません。拒否・取消・アプリ更新後の権限変化を
通常の状態として画面に表示できる設計にします。

## 起動と確認

1. Node.js 24.19以上の24系、pnpm 11.19を用意し、リポジトリを取得する。
2. `pnpm install --frozen-lockfile` → `pnpm build` → `pnpm init-local`。
3. `pnpm diagnose`で環境と設定の有無を確認する。権限・プロバイダー接続を検証するコマンドではありません。
4. `pnpm start`し、`http://127.0.0.1:4317`を開く。
5. `.innovox/access-token`に生成されたInnoVox用アクセスキーで接続する。
6. 「動作サンプルを開く」で保存・回答の流れを確認する。サンプルはAPIを呼びません。
7. OpenAIの認証設定が整った環境で、実際のAstra分析とGPT Live音声を別途確認する。

Cloud接続先はHTTPSを使用します。ローカルのSQLiteファイルはMacのローカルディスクに置き、
複数のPCやクラウドノードで同時に開く共有ファイルにはしません。

## Macの受入項目

- Apple Silicon / Intelは別に記録。ブラウザ、macOS、Node、コレクターの版を記録する。
- マイク許可、拒否、再許可、装置変更、ヘッドホン切断。
- 話しかけてから聞き返し、訂正、回答確定まで自然な会話を3回連続で確認する。
- Codex/Claudeへの切替、別プロジェクトへの切替中も回答の宛先が保持される。
- ネットワーク切断・復帰、Macのスリープ・復帰、ブラウザ終了後にマイクが止まる。
- 日本語、長い会話、ログの末尾への追記、途中のJSON、ログ切替、圧縮・分岐。
- 画面取得を将来追加した場合は、対象ウィンドウ切替、複数ディスプレイ、画面権限取消、
  秘密情報の除外、画像差分の頻度とCPU負荷を確認する。
- 配布用ネイティブアプリを追加する場合は、署名・公証・安定したbundle ID・更新手順・
  権限の再確認まで含める。[Apple: 公証](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)

## 1台で動かす場合の品質

クラウドモデルを使うローカル設置と、推論・ASR・TTSをすべてPCで行う完全ローカルは
別です。後者のモデル品質、遅延、メモリ容量、消費電力は未測定です。
Astraと同品質を任意のMacで実現できるとは約束しません。同じ評価データと受入基準を使い、
必要なハードウェアと未達部分を測って公開する方針です。
