# InnoVox

**人間とコーディングエージェントの間で、文脈と音声対話をつなぐ基盤。**

会話と作業の進行を読み、プロジェクトが大切にしている目的・保持条件と
照らし合わせて、今伝えると役立つ情報を先回りして提示します。
人間の判断が必要なら音声で相談し、答えを正しい作業へ戻します。

[English](README.md) · [起動と運用](docs/operations.md) · [Macの機能・設定](docs/platforms/macos.md) · [設計](docs/architecture.md) · [開発段階](docs/roadmap.md)

## 現在の状態

単一ユーザー向けの初期プレビューを実装しています。会話の取り込み・保持条件・
確認・回答を永続化し、ブラウザで操作できます。Codex/Claude Codeの選択した
会話ログを読み取るコレクターも含みます。

GPT LiveのWebRTC接続とAstraの判断を行う接続部には契約テストがありますが、
実API接続と人間による音声確認は未完了です。画面の自動取得・既存セッションへの
自動入力は未実装で、公開サービスもまだ稼働していません。

## 起動

Node.js 24.19以上の24系とpnpm 11.19を用意します。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm init-local
pnpm start
```

`http://127.0.0.1:4317`を開き、`.innovox/access-token`のInnoVox用アクセスキーで
接続します。「動作サンプルを開く」はOpenAI APIを呼びません。
`pnpm check`で検証、`pnpm diagnose`で環境と設定の有無を確認できます。
Macで必要な権限や未対応機能は[Mac向け手順](docs/platforms/macos.md)を参照してください。

## 目指す体験

- LLMがAskUserを呼ぶ前でも、必要な前提や見落としそうな条件を補える。
- 人間は作業を止めて長文を入力せず、口頭で意図を伝えられる。
- CodexからClaudeへ画面を切り替えても、回答の宛先を取り違えない。
- プロジェクトの目的、保持条件、その理由と訂正の履歴を引き継げる。

まずクラウドで動く体験を優先し、音声はGPT Live、判断はAstraを基本方針とします。
接続にはGPT Liveの公開APIを使い、InnoVox専用のAPIキーを新規作成する方針が
確定しています。キーの作成完了と認証済みの実接続は、まだ確認できていません。
その後、公開された仕様と同じ検証基準で、セルフホストと1台のPCでの利用へ広げます。
APIを使うセルフホストと、推論を含む完全ローカル動作は別の段階として検証します。

## 開発

小さく動く一連の機能を積み上げます。接続部は交換可能にし、バージョン差、
再接続、回答の訂正、誤配送、遅延を初期の受入条件に含めます。
未検証の機能や合成デモを、実接続済みとして扱いません。

詳細は[ロードマップ](docs/roadmap.md)と[開発ルール](AGENTS.md)を参照してください。
